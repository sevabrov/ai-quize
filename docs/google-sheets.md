# Запис результатів у Google Таблицю

Код уже в проєкті. Лишилося створити таблицю й підставити два значення в `.env`.

**Один рядок = одна людина.** Рядок створюється на завершенні квізу і
**дописується** (не дублюється), коли людина бронює консультацію.

---

## Колонки

| # | Колонка | Звідки |
|---|---|---|
| A | Пройдено | час завершення діагностики |
| B | ID сесії | ключ рядка з `localStorage` (`ai-quiz:session-id:v1`) |
| C | Про себе | питання 1 повністю: ім'я, вік, місто, опис — одним блоком |
| D | Профіль | назва фінального бізнес-профілю |
| E | Бали | топ-3 профілі з балами |
| F | Відповіді | `2c · 3a · 4d …` |
| G | Консультація | `Так` / `Ні` |
| H | Пошта | Cal.com → `responses.email` |
| I | Телефон | Cal.com → `responses.attendeePhoneNumber` |
| J | Telegram | Cal.com → `responses.Telegram` |
| K | Дата консультації | Cal.com → `startTime`, київський час |
| L | Zoom | посилання на зустріч |
| M | Коментар | `responses.notes` |
| N | Оновлено | час останнього запису |

H–M заповнюються лише для заброньованих; у решти вони порожні, а G = `Ні`.

---

## Налаштування (5 хвилин)

1. Відкрити **свою** таблицю на Google Диску (або створити нову).
2. У ній: `Розширення → Apps Script` → замінити вміст `Code.gs` вмістом файлу
   [`google-apps-script/Code.gs`](../google-apps-script/Code.gs).

   Скрипт, створений таким шляхом, прив'язаний саме до цього файлу — нічого
   додатково вказувати не треба. Якщо ж скрипт створюється окремо
   (`script.google.com`), заповніть у ньому `SPREADSHEET_ID` — розділ
   «Куди саме пишуться дані» нижче.
3. Поміняти `SECRET` на довгий випадковий рядок.
4. `Розгорнути → Новий розгорток → Тип: Веб-додаток`:
   - **Виконувати як:** Я
   - **Хто має доступ:** Усі (`Anyone`)

   > При першому деплої Google покаже «Додаток не перевірено» →
   > `Додатково → Перейти до …`. Це нормально для власного скрипта.
5. Скопіювати URL виду `https://script.google.com/macros/s/AKfy.../exec`
   і відкрити його в браузері — має віддати `{"ok":true,...}`.
6. Вписати в `.env`:

   ```bash
   VITE_SHEETS_URL=https://script.google.com/macros/s/AKfy.../exec
   VITE_SHEETS_SECRET=той-самий-рядок-що-і-в-Code.gs
   ```

7. Перезапустити `npm run dev` (Vite читає `.env` лише на старті).

Порожній `VITE_SHEETS_URL` = запис вимкнено, квіз працює як раніше.

## Куди саме пишуться дані

Скрипт має знати два орієнтири: **файл** таблиці і **аркуш** (вкладку) в ньому.

### Файл

| Спосіб | Що робити | Коли зручно |
|---|---|---|
| **Прив'язаний скрипт** ✅ | Відкрити таблицю → `Розширення → Apps Script`. `SPREADSHEET_ID` лишити порожнім | Звичайний випадок: одна таблиця, скрипт живе всередині неї |
| Окремий скрипт | Створити на `script.google.com`, у `SPREADSHEET_ID` вписати ID таблиці | Один скрипт на кілька таблиць, або скрипт треба тримати окремо від файлу |

ID береться з адреси таблиці — це довгий рядок між `/d/` та `/edit`:

```text
https://docs.google.com/spreadsheets/d/1AbC…XyZ/edit#gid=0
                                        └──── ось це ────┘
```

Для окремого скрипта акаунт, від імені якого зроблено розгорток
(«Виконувати як: Я»), має мати **право редагування** цієї таблиці.

### Аркуш

Константа `SHEET_NAME` (за замовчуванням `Заявки`) — це назва вкладки внизу
таблиці. Якщо такої вкладки немає, скрипт створить її сам і додасть шапку.

Тому в уже наповнену таблицю з іншими даними нічого не «вливається» —
квіз пише у власну вкладку поруч. Це навмисно: порядок колонок задає
`COLUMNS` у скрипті, і дописування в чужу шапку зсунуло б дані.

Якщо треба писати саме в наявну вкладку — впишіть її назву в `SHEET_NAME`
і приведіть її шапку до порядку з `COLUMNS` (або навпаки — переставте
рядки в `COLUMNS` під свою шапку; ключі зліва змінювати не можна).

## Telegram у Cal.com

Щоб колонка J заповнювалась, в event type `test-consultation` →
**Advanced → Booking questions** має бути поле з ідентифікатором `Telegram`
(зараз воно вже є) та увімкнений `Attendee phone number`.
Якщо поле перейменувати — поміняти ключ у
[`readCalDetail`](../src/lib/sheets.ts).

## Перевірка

1. `npm run dev:all`
2. Пройти квіз до результату → у таблиці новий рядок, `Консультація = Ні`.
3. Забронювати слот → **той самий** рядок, `Консультація = Так` + контакти й дата.

Якщо рядок не з'явився — DevTools → Network → запит на `/exec`:

| Симптом | Причина |
|---|---|
| помилка CORS / preflight | зміна `Content-Type` у `sheets.ts` — має лишатись `text/plain` |
| `{"ok":false,"error":"forbidden"}` | секрет у `.env` ≠ секрет у `Code.gs` |
| запиту взагалі немає | порожній `VITE_SHEETS_URL` або Vite не перезапускали |
| 302 / порожня відповідь | розгорток зроблено не як «Anyone» |

> Після кожної зміни коду в Apps Script потрібен **новий розгорток**
> (`Розгорнути → Керувати розгортками → олівець → Версія: Нова`),
> інакше працює стара версія.

## Як це влаштовано в коді

- [`src/lib/sheets.ts`](../src/lib/sheets.ts) — транспорт і форматування.
  Fire-and-forget: помилка мережі ніколи не ламає квіз.
- [`src/hooks/useQuizFlow.ts`](../src/hooks/useQuizFlow.ts) — дві точки виклику:
  ефект завершення діагностики та `registerBooking`.
- Ключ рядка навмисно береться з `localStorage`, а не з json-server: у проді
  json-server немає, і прив'язка до нього дала б порожню таблицю.
- Перезавантаження сторінки після завершення надсилає рядок ще раз. Це не баг:
  upsert по тому самому ключу переписує ті самі значення й водночас дає
  безкоштовну повторну спробу, якщо перша відправка не долетіла.

## Обмеження, про які варто знати

- **Секрет видно в бандлі.** Він відсікає випадкових ботів, але це не справжній
  захист. Якщо треба закритий ключ — виносити запис на serverless-функцію з
  Service Account (контракт залишиться той самий).
- **Персональні дані.** У таблиці лежать пошта, телефон, Telegram — не давати
  доступ «усім за посиланням».
- **Запис із браузера** втрачається, якщо людина закриє вкладку в момент успіху
  (`keepalive: true` це майже завжди рятує). Якщо знадобиться стовідсоткова
  надійність по бронюваннях — додати webhook Cal.com `BOOKING_CREATED` на той
  самий `/exec` як дублер.
- **Ліміт Apps Script** — близько 20 000 запитів на добу. Для цього квізу з запасом.
